# AI/RAG 포트폴리오 사이트 보완 가이드

첨부된 현재 디자인을 기준으로, 포트폴리오 사이트로서 더 신뢰감 있고 실제 의뢰로 연결될 수 있도록 보완할 내용과 디자인 수정 방향을 정리한 문서입니다.

---

## 1. 현재 디자인 총평

현재 디자인은 전체적으로 **AI/RAG 기반 B2B SaaS 스타일**이 잘 잡혀 있습니다. 딥 네이비 배경, 시안 포인트 컬러, 카드형 구성, 넓은 여백 덕분에 전문적이고 신뢰감 있는 인상을 줍니다.

다만 현재 구조는 개인 포트폴리오라기보다 **AI 서비스 소개 랜딩페이지**에 더 가깝습니다. 포트폴리오로 사용하려면 다음 요소가 보완되면 좋습니다.

- 이 사람이 누구인지 보여주는 **About / 소개 섹션**
- 실제 경험과 강점을 보여주는 **경력·역량 요약**
- 프로젝트가 실제 구현인지, 기획안인지 구분하는 **프로젝트 상태 표시**
- 의뢰자가 이해하기 쉬운 **서비스 제공 범위**
- 문의 전에 신뢰를 높이는 **작업 방식·협업 방식 설명**

## 3. 추가하면 좋은 섹션

## 3-1. About / 소개 섹션

### 추가 위치

Hero 섹션 바로 아래, Core Expertise 섹션 위에 배치하는 것이 가장 자연스럽습니다.

### 섹션 목적

방문자가 다음 질문에 답을 얻도록 만드는 섹션입니다.

- 이 사람은 어떤 배경을 가진 사람인가?
- 왜 AI/RAG 서비스를 만들 수 있는가?
- 개발 경험과 교육 경험이 어떻게 강점으로 연결되는가?
- 단순 개발자가 아니라 문제 해결형 서비스 설계자인가?

### 추천 문구

```text
ABOUT
문제를 이해하고, 서비스로 구현하는 AI/RAG 개발자

프론트엔드 개발과 교육 경험을 바탕으로, 사용자의 업무 흐름을 이해하고 실제로 사용할 수 있는 AI 기반 서비스를 설계합니다. 최근에는 RAG, 멀티모달 AI, TTS/STT, 프롬프트 엔지니어링을 중심으로 문서 검색, AI 챗봇, 업무 자동화 서비스를 연구하고 구현하고 있습니다.
```

### 강조 카드 3개

```text
Frontend & Service UI
웹 서비스 화면 설계와 사용자 흐름 구현 경험

AI/RAG Workflow

Education & Consulting
복잡한 기술을 쉽게 구조화하고 설명하는 교육자 관점
```

## 3-2. Why Me / 차별점 섹션

포트폴리오 사이트에서는 “왜 이 사람에게 맡겨야 하는가?”가 중요합니다. About 섹션과 겹치지 않게, 핵심 강점을 짧게 보여주는 섹션을 추가하면 좋습니다.

### 추천 제목

```text
WHY WORK WITH ME
기술보다 먼저, 실제 업무 문제를 봅니다.
```

### 추천 내용

```text
단순히 AI 기능을 붙이는 것이 아니라, 사용자가 실제로 겪는 문서 검색, 반복 업무, 고객 응대, 자료 정리 문제를 먼저 정의합니다. 이후 작은 PoC로 검증하고, 필요한 기능만 단계적으로 확장하는 방식으로 서비스를 설계합니다.
```

### 추천 카드 구성

```text
문제 정의 중심
사용자의 업무 흐름과 병목 지점을 먼저 정리합니다.

작게 검증하는 PoC
처음부터 큰 시스템을 만들기보다 빠르게 테스트 가능한 구조로 시작합니다.

운영 가능한 구조
관리자 화면, 데이터 관리, 유지보수까지 고려한 서비스를 지향합니다.
```

## 3-4. Project Status / 프로젝트 상태 표시

현재 프로젝트 섹션은 시각적으로 좋지만, 실제 프로젝트인지 기획안인지 구분이 약합니다. 포트폴리오 신뢰도를 위해 각 카드에 상태 배지를 넣는 것을 추천합니다.

### 추천 상태 배지

```text
Prototype
기획 및 화면 설계 중심

In Progress
현재 구현 또는 테스트 진행 중

Case Study
문제 해결 방식과 설계 과정을 정리한 사례

Released
실제 배포 또는 운영 경험이 있는 프로젝트
```

### 프로젝트 카드 예시

```text
교육 자료 통합 검색 어시스턴트
```

```text

분야: AI Chatbot / Customer Support
설명: 서비스 정보와 FAQ를 기반으로 고객 문의에 응답하는 챗봇 구조 설계
```

```text

분야: Workflow Automation
```

## 5. 디자인 보완 제안

## 5-1. Hero 영역

현재 Hero 영역은 첫인상이 좋습니다. 다만 오른쪽 UI 카드가 조금 더 “RAG 서비스”처럼 보이면 좋습니다.

### 보완 방향

- 오른쪽 카드 제목을 `RAG Pipeline / Live`처럼 유지
- 카드 항목을 실제 RAG 흐름처럼 보이게 구성
- 예: 문서 업로드 → 벡터 검색 → 답변 생성 → 출처 표시

### 추천 카드 텍스트

```text
01 Document Ingestion
PDF · Web · Manual · FAQ

02 Vector Search
Embedding · Retrieval · Ranking

03 AI Answer
Summary · Response · Source

04 Service UI
Chatbot · Admin · Dashboard
```

## 5-4. Working Process 섹션

현재 프로세스 섹션은 좋습니다. 다만 `PoC 구현`이라는 용어는 비전문 방문자에게 어려울 수 있습니다. 괄호로 설명을 붙이면 좋습니다.

### 추천 문구

```text

서비스 목적, 사용자, 데이터, 반복 업무 흐름을 정리합니다.

02 데이터 진단
문서 구조와 검색 가능성을 확인하고 RAG 적용 범위를 판단합니다.

03 PoC 구현
작은 기능부터 테스트 가능한 형태로 구현해 가능성을 검증합니다.

04 운영·개선
피드백을 반영해 관리자 기능, 자동화, 확장 구조를 개선합니다.
```
