# 오픈디자인용 포트폴리오 사이트 디자인 프롬프트

## 프로젝트 개요

AI 에이전트, RAG 기반 서비스, 업무 자동화, 문서 지식화 서비스를 만드는 개인 포트폴리오 사이트를 디자인하기 위한 프롬프트입니다.

이 사이트는 단순한 개인 소개용 포트폴리오가 아니라, 앞으로 지속적으로 업데이트하며 **RAG 기반 AI 서비스 제작자 / 실무형 AI 전환 파트너 / 문서 기반 AI 자동화 서비스 개발자**로 확장해 나가기 위한 기반 사이트입니다.

- 단순한 개발자가 아니라, 업무 흐름을 이해하고 AI 서비스로 구현하는 실무형 솔루션 제작자
- 너무 기술자처럼 어렵게 보이지 않되, 충분히 신뢰감 있고 전문적으로 보여야 함
- 방문자가 “내 문서와 업무도 AI 서비스로 바꿀 수 있겠구나”라고 느껴야 함

# 2. 주의사항 프롬프트

```txt
주의사항:

- 너무 강사 소개 사이트처럼 보이면 안 됨
- 교육 경력이나 강의 이력을 전면에 내세우지 말 것
- “AI를 가르치는 사람”보다 “AI 서비스를 실제 업무에 적용해주는 사람”으로 보이게 할 것
- 너무 개발자 포트폴리오처럼 코드, 깃허브, 기술 스택만 강조하지 말 것
- 너무 컨설턴트처럼 추상적인 말만 많고 결과물이 없어 보이면 안 됨
- 방문자가 이해하기 어려운 전문 용어를 과도하게 사용하지 말 것
- RAG, Vector DB, Embedding 같은 단어는 사용하되 쉬운 설명과 함께 배치할 것
- 너무 가벼운 스타트업 느낌보다 신뢰감 있는 B2B 서비스 느낌을 유지할 것
- 과도한 네온, 사이버펑크, 복잡한 3D 그래픽은 피할 것
- 한국어 문장에 부자연스러운 자간이나 너무 얇은 폰트 사용을 피할 것
- 86px 이상의 초대형 타이포는 한국어에서는 부담스러울 수 있으므로 Hero 타이틀은 56~72px 정도로 조정할 것
- 모바일에서도 섹션 구분과 CTA가 명확하게 보이도록 설계할 것
- 카드가 너무 많아 산만해 보이지 않게 하고, 큰 섹션 블록 중심으로 구성할 것
- 포트폴리오 프로젝트는 “예쁜 결과물”보다 “해결한 문제, 사용 기술, 적용 가능성”이 보이도록 디자인할 것
- AI 서비스 제작자로 성장 중이라는 느낌은 주되, 미완성처럼 보이지 않게 “진행 중인 전문 분야”로 표현할 것
- 너무 기술자 중심의 어휘만 사용하지 말고, 고객이 얻는 결과를 함께 표현할 것
- 신뢰감, 전문성, 실용성이 함께 느껴지도록 할 것
- 사이트 전체가 개인 브랜딩과 서비스 소개를 동시에 할 수 있는 구조가 되도록 할 것
```

# 추천 파일 사용 방법

1. 오픈디자인에 먼저 **시각요소 프롬프트**를 넣어 전체 디자인 방향을 잡습니다.
2. 이어서 **주의사항 프롬프트**를 넣어 피해야 할 디자인 방향을 명확히 합니다.
3. 마지막으로 **추천섹션 프롬프트**를 넣어 실제 페이지 구조를 생성합니다.
4. 결과물이 나오면 Hero, About, Project 섹션부터 우선 수정하면서 개인 포트폴리오에 맞게 다듬습니다.
